# FORK.md

How this fork stays mergeable with upstream Handy. Written after the v0.9.5
sync, from what that merge actually cost.

## The numbers that shaped these rules

v0.9.5 brought 41 upstream commits. 25 files were touched by both sides, and
only 9 of them conflicted. Every conflict was in a file upstream owns and this
fork edited. Files this fork added outright — `media_control.rs`,
`paste_target.rs`, `PausePlaybackWhileRecording.tsx`, `PttDoubleTapLock.tsx` —
conflicted zero times, and the ~12 Windows/Linux commits and 4 translation
commits merged without a single hunk to look at.

So the cost of a sync is not the size of the release. It is the size of the
overlap.

## Rules that keep the overlap small

**New behavior goes in a new file with one call site.** A feature that lives in
its own module is invisible to upstream's diffs forever. A feature spread across
three upstream functions is a conflict in each of them, at every release.

**Never rename or replace an upstream symbol — wrap it.** `change_binding` was
rewritten in place as `set_binding_shortcuts`, which turned a one-line upstream
patch (`secure_input::reconcile_fallback`) into a 69-line conflict, twice. Where
the wrapper approach was used instead (`change_binding` still exists and
delegates), upstream's edits merged clean.

**When behavior must change inside an upstream function, hide the change behind
one fork-owned call.** `should_send_auto_submit(...)` and
`paste_target::typing_style(...)` are the pattern: upstream can edit the lines
around them freely. That is why `clipboard.rs` auto-merged textually.

**Keep the fork's invariants in tests, not in your head.** Every bug this merge
introduced would have been caught mechanically by a test that already knew what
the fork guarantees. That is the highest-value work available here.

## Resolution policy, per file

| file                        | what to do                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| `src-tauri/Cargo.lock`      | take upstream's; `cargo build` reconciles the fork's deps                                      |
| `src-tauri/Cargo.toml`      | check for a dependency **both** sides added — a duplicate key makes the manifest unparseable   |
| `src/bindings.ts`           | generated by tauri-specta; keep it consistent by hand, a debug run rewrites it authoritatively |
| `src-tauri/tauri.conf.json` | keep this fork's `productName` and signing identity, take upstream's `version`                 |
| `README.md` / `LICENSE`     | keep the fork's README wholesale; LICENSE keeps both copyright lines                           |
| everything else             | keep the fork's behavior and graft upstream's new calls into it; never take a side wholesale   |

## The four hazard shapes

Ranked by how much damage they did in the v0.9.5 sync. The first three were
found by an audit pass, not by the conflict markers — two of them were in files
that merged _without_ conflict.

1. **Both sides added the same thing.** `objc2-app-kit` appeared twice in
   `[target.'cfg(target_os = "macos")'.dependencies]`. Cargo refuses to parse.
2. **Upstream renamed a command the fork calls.** `suspend_binding` /
   `resume_binding` became no-arg `suspend_all_bindings` / `resume_all_bindings`;
   the fork's four call sites failed `tsc`. `tsc` catches this class — run it.
3. **An upstream early return skipped a fork gate.** The new receipt-sequenced
   paste returned `Ok(())` before `should_send_auto_submit`, so a re-pasted
   historical transcript would have pressed Enter. Nothing conflicted; the
   fork's own tests passed, because they tested the gate function and not the
   path through it.
4. **Upstream cloned a struct the fork extended.** The Secure Input Carbon
   shadow copied the whole binding, including this fork's `extra_bindings`, so
   alternates could double-register or strand a registration.

## Running a sync

```sh
scripts/sync-upstream.sh plan            # read-only: cost of the newest release
scripts/sync-upstream.sh plan upstream/main
scripts/sync-upstream.sh start [TAG]     # branch + merge, stops at conflicts
scripts/sync-upstream.sh verify [--quick]
```

`verify` is the ladder: `cargo fmt --check`, `cargo test`, `tsc`, `vite build`,
the translation checker (reported, not gating — see below), and the release
bundle. Install by hand, between dictations, and keep the previous `.app` for
rollback.

`scripts/upstream-watch.sh` runs weekly from
`~/Library/LaunchAgents/com.handy.upstream-watch.plist` (Mondays, 9:07): it
fetches upstream, writes a dated report to `~/handy-review/upstream/`, and
notifies once per release that this fork hasn't merged. A quiet week is silent.

Sync every release. Drift is what makes a merge expensive: at v0.9.5 the fork's
merge base was 19 days old and 9 files collided, and each skipped release leaves
a hole that every later commit conflicts against. Merging the release tag (not
cherry-picking commits out of it) is what records ancestry, so the next sync only
sees what is new.

## Sync record

**v0.9.6, 2026-08-25.** 5 incoming commits, 14 files touched by upstream, 2
conflicts: `actions.rs` and `tauri.conf.json` (a version bump). The release
notes list 20 PRs, but four of the five that could have hurt this fork —
appearance-reaches-the-overlay (#1659), the filler fixes (#1738), multi-word
custom words (#1406), transcribe.cpp 0.2.0 (#1924) — were already ancestors of
this branch from an earlier `main` merge, and the fork had already answered
#1659 by pinning the flow bar's colours. So the whole cost of the release was
the single-writer tray (#1952): `change_tray_icon` became `set_tray_state`,
`CurrentTrayIconState` became `TrayState`, and `update_tray_menu` lost its
locale argument. `tray.rs` was taken wholesale — the fork's only edit in that
file was one field in a test helper.

The conflict markers caught 12 of the 14 renamed call sites in `actions.rs`.
The two they missed sit in a region this fork rewrote (the editing-key quiet
window), so the merge had nothing to disagree about and kept the old name.
That is hazard shape 2 arriving in Rust instead of TypeScript, where `tsc`
would have caught it: after an upstream rename, grep the old symbol across the
whole tree. A file that merged cleanly _because_ the fork restructured it is
exactly where a stale name survives.

## Known fork-vs-upstream inconsistencies

- `bindings.ts` spells the settings enums `min_15` / `hour_1`, while serde — and
  therefore the dropdowns and `settings_store.json` — uses `min15` / `hour1`. The
  UI casts past the mismatch. A test pins the serialized names.
- The translation checker fails on 49 keys this fork added in English only (34
  after v0.9.5; the fork has added keys since). A sync should leave that number
  unchanged, not reduce it to zero.
- The tray tooltip and the disabled version item at the top of its menu read
  `Handy v0.9.6`. The branding sweep covered the i18n strings; this one is
  formatted in `tray.rs` from `CARGO_PKG_VERSION` and was missed. It predates
  the v0.9.6 sync.
- `mute_while_recording` is still honored in Rust with no UI to reach it; the
  toggle was dropped on purpose.

## Building a copy for someone else

    bun run tauri build --bundles app --config export.conf.json

The override exists for one reason: the app's own identifier is still
`com.pais.handy`, upstream's. A build carrying that collides with an installed
Handy on the recipient's machine, shares its settings and permissions, and — as
three failed test runs showed — cannot even be launched alongside one, because
the single-instance plugin forwards to whichever copy is already running. Under
its own identifier it is a separate app to macOS: separate data, separate
microphone and accessibility grants, separate instance lock.

Do not build the copy you use daily with this override. Your recordings and
settings live under `com.pais.handy`, and a different identifier means a
different data directory — the app would come up empty.

The build is signed with a local identity and is not notarized, so Gatekeeper
blocks it on any other Mac. The recipient right-clicks the app and picks Open
the first time; every launch after that is normal.

## Publishing as its own repo

The legal position, verified against upstream's terms:

- Upstream is MIT (Copyright (c) 2025 CJ Pais). Redistribution, modification,
  and public forks are all permitted; the one obligation is that the copyright
  and permission notice stay in LICENSE, which it does (with this fork's line
  added beside it).
- Upstream's README reserves the Handy **name, logo, icon, and brand assets**
  — forks must use their own branding and not imply endorsement. Satisfied:
  the app is named Fancy Shmancy, ships its own icon set, and the last
  user-facing "Handy" strings were renamed. The bundle identifier for
  distributed builds is `com.remtbkv.fancyshmancy`, not `com.pais.handy`.
- Models are not shipped in the repo or the app; they download on first run
  under their own licenses. The recommended three are Apache-2.0 and
  CC-BY-4.0 — no non-commercial terms in the default path.

When the repo goes public, prefer a **fresh repository** (one initial commit,
or a squashed import of this branch) over flipping this fork public: the
history here documents reverse-engineering a commercial app's UI in detail
and references the author's personal corpus. The working tree is publishable;
the history is not. Keep this checkout as the private working copy that
carries upstream ancestry for syncs, and push snapshots to the public repo.

To make a friend's install one download instead of a toolchain: create a
GitHub Release on the public repo and attach the built `.app` (zipped) from
the export recipe above, with the right-click-Open note in the README doing
the Gatekeeper work.
